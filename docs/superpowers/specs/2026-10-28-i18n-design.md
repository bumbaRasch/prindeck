# UI localization (10 languages) — Design

- Status: draft for approval (builder check done 28.10.2026: three findings —
  one settled by the author as decision 6, two resolved as maintainer calls,
  see §2, §5, §7)
- Phase: new milestone before M5 — publication explicitly waits for this
  (author's decision 28.10.2026).
- Sources: MDN via context7 checked 28.10.2026 (`navigator.languages` —
  BCP-47 tags ordered by user preference; `navigator.language` — first of
  them; `Accept-Language` mirrors the list). Ecosystem survey via searxng
  28.10.2026 (i18next, Lingui, intl-messageformat/FormatJS, fluent.js).
  Repo facts: `ui/src/labels/` — 6 files, 199 lines, Russian strings;
  consumers import named exports (`TEXT`, `CHIP_LABELS`, `SIDES_LABELS`,
  `updatedSecondsAgo`, `formatSizeKb`) in 10+ screen modules;
  `scripts/check-code-language.sh` enforces "Russian strings only in
  `ui/src/labels/` and `*_LABEL` constants". Tauri 2 docs via context7,
  checked 28.10.2026: notification plugin JavaScript API is the documented
  send path (`isPermissionGranted` → `requestPermission` → `sendNotification`
  from `@tauri-apps/plugin-notification`, tauri.app/plugin/notification);
  `TrayIcon::set_menu` on Linux — a set menu cannot be removed, but its
  content can be changed (docs.rs/tauri 2.9.x, platform-specific notes).

## Intent

PRD §8 promises a UI that follows the system locale with an English
fallback. Publishing with a Russian-only UI would narrow the audience to
Russian speakers on day one. This milestone delivers the localization
mechanism and ten complete locale catalogs **before** the GitHub
publication (M5), so the first public build is usable worldwide.

## Decisions (made with the author)

1. **Ten languages**: English `en`, Russian `ru`, Ukrainian `uk`, German
   `de`, French `fr`, Spanish `es`, Portuguese (Brazil) `pt-BR`, Chinese
   (Simplified) `zh-CN`, Japanese `ja`, Arabic `ar`. The author named
   en/de/fr/es/zh/ar; `ru` is the existing base language; `pt-BR`/`ja`/`uk`
   are this document's proposal (largest reachable Linux audiences the
   author can partially verify). Reserves if one is rejected: Polish,
   Turkish, Indonesian, Korean. Swapping a language before implementation
   is a one-file change.
2. **Drafts by LLM, ownership by community**: every non-English catalog
   starts as an LLM draft produced against a per-language glossary;
   improvements arrive as PRs and are re-checked by the maintainer. The
   author personally verifies `en`, `ru`, `uk`. No AI-humanizer SaaS in the
   pipeline: those tools target long prose and AI-detector evasion, not
   terse UI labels, and LLM drafts do not have the staleness of classic
   MT. The real draft risks are terminology drift and placeholder drift —
   both covered by the glossary and mechanical checks (§4).
3. **Approach A — zero dependencies** (see Approaches).
4. **Language selection: system locale only.** `navigator.languages` at
   startup → exact tag match → language-only match (`pt-PT` → `pt-BR`,
   `zh-TW` → `zh-CN`; known imperfection, accepted) → English fallback.
   No persisted override, no settings control, **no backward
   compatibility** with the Russian-only UI (author: not needed at all —
   the app has no users yet).
5. **M5 waits for this milestone** (author's decision; the glib/tauri
   stack bump stays a separate queued item, not part of this design).
6. **All user-visible wording lives in the frontend catalogs** (author:
   "b, максимально чисто, по докам"). The backend stops wording messages
   and emits structured kinds + params; the frontend maps them through
   `t()`. See §6.
7. **Maximally by-the-docs**: every mechanism used is the documented
   Tauri 2 path — the notification plugin's JavaScript API for showing
   notifications, `TrayIcon::set_menu` for tray-menu content, plain
   serde'd command results for structured errors. No undocumented
   workarounds, no new Rust crates.

## Approaches

- **A — typed catalogs + native `Intl`, zero dependencies (chosen)**:
  per-locale TS modules under `ui/src/locales/`, a small `ui/src/i18n.ts`
  runtime (detection, `t()`, plurals, relative time). Plural correctness
  for every locale comes from the engine (`Intl.PluralRules`), key parity
  from `npm run typecheck` (a missing key is a type error) — CI needs no
  new checks. Fits PRD §5.2/§10 dependency discipline literally.
- **B — `intl-messageformat` (rejected)**: standard ICU message syntax
  and CAT-tool familiarity, but a runtime dependency that parses messages
  on the fly for ~200 strings. Overkill.
- **C — `i18next` (rejected)**: the ecosystem standard, but
  framework-shaped: its own package cluster, detection and fallback
  machinery we re-implement in ~60 lines anyway. Against the crate/package
  discipline.
- Fluent (fluent.js) — considered and dropped: `.ftl` files and tooling
  nobody else in this stack knows; for this catalog size it is weight
  without benefit.

**Backend-owned strings** (tray menu, notifications, print/config error
texts — found by the builder check) had its own fork:

- **a — frontend-only now** (rejected): ships an English/German/… UI with
  a Russian tray menu and Russian notifications; contradicts the intent
  ("first public build usable worldwide").
- **b — backend emits kinds + params, frontend words them (chosen)**:
  event payloads and command errors become structured; notification
  display moves to the frontend through the plugin's documented JS API;
  the tray menu is rebuilt from labels delivered over IPC. Single source
  of wording, zero new crates; also kills the existing substring-parsing
  of config errors in `settings_values.ts`.
- **c — parallel catalogs in Rust** (rejected): a new i18n crate against
  the fixed §10 list plus duplicated catalogs in two languages of
  implementation. Worst of both.
- Frontend-built tray via the JS tray/menu APIs — rejected: the icon must
  exist before the webview loads (Linux tray quirks are already handled
  in Rust); label delivery over IPC is simpler and equally documented.

## The parts

### 1. Locale set and codes

`en`, `ru`, `uk`, `de`, `fr`, `es`, `pt-BR`, `zh-CN`, `ja`, `ar`.
`en` is the source-of-truth catalog (key set and param names derive from
its type); every other locale `satisfies Catalog` where
`type Catalog = typeof en`. BCP-47 tags in file names use underscores on
disk (`pt_br.ts`, `zh_cn.ts`) or kebab — builder's call, consistent
everywhere.

### 2. Detection and startup wiring

At startup, before any screen renders: read `navigator.languages`, walk it
against the supported tags (exact match first, then language-only), fall
back to `en`. The chosen locale sets `document.documentElement.lang` and,
for `ar`, `dir="rtl"` (script direction map, not a locale list: any future
RTL locale gets it for free). No `languagechange` listener — a system
locale change is picked up on the next app start (restart is acceptable;
live re-translation is complexity without a user). *(my call)*

`ui/index.html` currently carries static Russian copy (nav labels,
banners, buttons, `<title>`, `lang="ru"`). It is stripped to unlabelled
elements with data hooks; the catalog populates everything synchronously
in module init, before any screen renders — no wrong-language first
frame in practice. *(my call, builder check)*

**Dev-only override**: the runtime honours a `PRINDECK_LOCALE` env var
above the system locale. Not a product feature — it exists so the
`visual-check` pass and manual testing can force `ar`/`pt-BR`/`zh-CN`
without regenerating system locales; documented in CONTRIBUTING as a
development hook. *(my call, builder check)*

### 3. Catalog format

Flat dot-namespaced keys (`"scan.title"`, `"overview.toner"`), string
values with `{name}` placeholders. Plural-bearing messages are objects
keyed by plural category:

```ts
"scan.pages": { one: "{n} page", other: "{n} pages" }
```

The runtime selects the category with `Intl.PluralRules(locale).select(n)`
— so `ru`/`uk` catalogs carry `one/few/many/other`, `ar` carries all six,
`zh`/`ja` carry only `other`; translators just fill the categories their
language has. `updatedSecondsAgo` and `formatSizeKb` move into the runtime
on top of `Intl.RelativeTimeFormat` / `Intl.NumberFormat`.

The existing `ui/src/labels/` modules are consumed: their strings seed the
`en` (re-worded as UI labels, not translations) and `ru` catalogs, then
the module directory is replaced by `ui/src/locales/`. Screens switch from
imported constants to `t("…")` calls — a mechanical sweep over the ten
consumer modules.

### 4. Mechanical quality gates

- **Key parity**: enforced by `typecheck` (`satisfies Catalog`) — no new
  script. *(my call)*
- **Placeholder parity**: the `t()` signature is typed against the `en`
  catalog's param names; a catalog with a wrong placeholder name is a type
  error. If a string-level check is cheaper at implementation time, a
  small lint in `scripts/` is allowed but not pre-decided.
- **Glossary**: `docs/i18n-glossary.md` per language for device terms
  (toner, drum, ADF/feeder, platen, duplex, queue) — the LLM drafts and
  future PR translators both work from it.

### 5. RTL pass (Arabic)

One-time audit of `ui/src/styles/` for logical equivalents
(`margin-inline-start` etc., `text-align: start`), fixing physical
properties that would mirror wrongly. Verification: the `visual-check`
subagent screenshots the `ar` locale at the smallest and largest window in
both themes (same acceptance bar as the AGENTS responsive rule); the
existing live scan/cancel checks are unaffected (UI-only change).

### 6. Backend wording → kinds (decision 6)

Today Russian user-visible text is produced in four Rust places; each
switches to structured data that the frontend words via `t()`:

- **Notifications** (`src-tauri/src/notify/`): the backend stops showing
  desktop notifications; it keeps the edge-trigger logic and emits the
  existing `alert` event (`{kind, params}` — `message` survives for logs
  only). The frontend listens and shows the notification through the
  plugin's documented JS API (`isPermissionGranted` → `requestPermission`
  → `sendNotification`), adding the npm binding
  `@tauri-apps/plugin-notification` — the JS half of the plugin already
  in the crate list, not a new plugin and not a new Rust crate.
- **Tray menu** (`src-tauri/src/tray/`): the icon keeps being built in
  Rust at startup (Linux requires a menu at creation); initial labels are
  the English fallback. Once the frontend has detected the locale it
  invokes a `set_tray_labels` command; the backend rebuilds the menu
  content via `TrayIcon::set_menu` (documented as content-changeable on
  Linux). A sub-second English tray before the webview reports the locale
  is accepted — it is also the fallback language. *(my call)*
- **Print errors** (`src-tauri/src/commands/print.rs`, 8 `PRINT_*_LABEL`
  strings): `print_file` errors become a kind enum in the payload; the
  Print screen words them.
- **Config validation** (`src-tauri/src/config/error.rs` +
  `get_startup_error`): `ConfigError` carries `{field, kind}` instead of
  English text; the settings screen maps it through `t()` and the
  substring matching in `settings_values.ts` (`fieldFromErrorText`) is
  deleted.

`scan-error` already carries a classified `kind` — only its Russian
`message` wording moves to the frontend.

### 7. Draft production

Per language: glossary + the `en` catalog → LLM translates → output lands
in `ui/src/locales/<tag>.ts` satisfying `Catalog` → typecheck green. The
author reviews `ru`, `uk` (and authored `en`); the other seven ship marked
as community-reviewable drafts. Where the marking lives (CONTRIBUTING
table vs a locale status comment) — builder's call. *(my call: table in
CONTRIBUTING)*

### 8. Repo rule and doc updates

- `scripts/check-code-language.sh`: the rule becomes "UI strings live only
  in `ui/src/locales/`" (English code everywhere; the `*_LABEL` exception
  dies with `labels/`). The script is updated in the same commit that
  deletes `labels/`.
- PRD: §8 localization paragraph rewritten (ten languages, matching
  order, en fallback, dev-only env override); §9 updated — notifications
  are shown by the frontend, `alert` carries `{kind, params}`,
  `set_tray_labels` added to the command table; §10 frontend note: the
  official JS binding `@tauri-apps/plugin-notification` added, no crates;
  roadmap gains this milestone before M5 (numbering: M4.7 or the plan
  renames — builder's call).
- AGENTS.md: the labels rule in "Rules" is replaced by the locales rule;
  the Russian-UI note is removed.
- CONTRIBUTING: how to add/fix a translation (edit one file per locale,
  parity is enforced by typecheck, glossary link, the verified-locales
  table).

### 9. Non-goals / out of scope

- No manual language override in settings (system locale only; the
  `PRINDECK_LOCALE` env var is a development hook, not a feature).
- No live re-translate on `languagechange`.
- No translation platform (Weblate/Crowdin) — GitHub PRs only.
- No ICU `select`/gender grammar — nothing in this UI needs it.
- No additional RTL locales beyond `ar` in this milestone.
- The glib/tauri/wry stack bump is a separate work item, untouched here.
