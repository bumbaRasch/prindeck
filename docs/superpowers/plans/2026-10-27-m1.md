## 1. Live spike: cancel and parallel requests ✅ 27.10.2026

Performed before writing code. The results — in `docs/escl-l2710dw.md` §10, the raw
logs — `/tmp/opencode/`.

| Question | Answer |
|---|---|
| `DELETE` during a blocking `NextDocument` | **`200`** in 0.42–0.60 s; the device is immediately `Idle` |
| What a hung `NextDocument` returns after `DELETE` | **`410 Gone`**, 0 B, after ~0.2 s — a normal cancel, not an error |
| `ScannerStatus` during a scan | answers immediately (0.41–0.62 s), full XML — polling is possible |
| `JobState=Completed` as a «document ready» trigger | **not suitable**: it lags, arrives only after `NextDocument` → `404` |
| `scan:Jobs` history | ring buffer of 16 entries, the oldest is evicted |

What follows from this for the code (taken into account in §4–§5):

- cancel = `DELETE` **on a separate connection**, without waiting for the fetch; the
  race «cancel vs completion» is resolved by the fetch code (`200` = made it, `410` = canceled);
- on cancel, delete the temporary file **unconditionally** (a cancel at the moment of a
  partial transfer has not been tested — a truncated file is possible);
- progress in M1 — client-side phases (`created → scanning → done`), status polling
  is not needed.

## 3. `config.rs` (small, but mandatory)

Without it, `EsclClient` would have to be constructed from hardcode — and that is
exactly the «silent default» the plan avoids.

```rust
#[derive(Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]   // unknown fields are ignored: the config
pub struct Config {                   // extends in M2/M4 without breaking old builds
    pub device: DeviceConfig,   // host: String ("192.168.187.36")
    pub scan_dir: PathBuf,      // default: documents/scans
}
```

- Path: `dirs::config_dir()/prindeck/config.json` (`~/.config/prindeck/`).
- No file → create it with defaults (host `192.168.187.36`, `scan_dir` =
  `dirs::document_dir()` with the fallback `home_dir()/Documents`, plus `/scans`).
- Validation at startup (PRD §5.5): host non-empty, `scan_dir` is created
  (`create_dir_all`), an error → a clear `ConfigError`, not a panic.
- `base_url()` → a `Url` of the form `http://<host>/eSCL/` (+ `Url` parsing, not
  string concatenation).

Unit tests: the default config serializes/reads round-trip; broken JSON →
`ConfigError`; empty host → error. The file system — via `tempfile`?
**No**: the crate is not declared in §10. Tests only on pure functions
(`Config::from_json_str`, `Config::defaults_for(home, documents)`).

## 4. `escl.rs` — the scanning core

The logic is carried over from `scripts/escl-probe.mjs` 1:1, but typed.

```rust
pub struct EsclClient { base: Url, http: reqwest::Client }

impl EsclClient {
    pub async fn capabilities(&self) -> Result<ScanCaps, EsclError>;
    pub async fn status(&self) -> Result<ScannerStatus, EsclError>;   // preflight + JobState
    pub async fn start(&self, params: &ScanParams) -> Result<Url, EsclError>; // POST → job URI
    pub async fn next_document(&self, job: &Url) -> Result<NextDoc, EsclError>;
    pub async fn cancel(&self, job: &Url) -> Result<CancelOutcome, EsclError>;
}

pub enum NextDoc { Document(Vec<u8>), End, Canceled }   // 200 | 404 | 410
pub enum CancelOutcome { Canceled, AlreadyFinished }    // 200 | 404
```

Why `status()` in M1: a preflight before `POST` (`pwg:State != Idle` →
«device busy» instead of catching `503`). It also provides `JobState` and `AdfState`
for the future — that is, not dead code.

Timeouts:

- the shared client `connect_timeout(5s)` + `timeout(5s)` for caps/status/POST
  (PRD §5.3);
- `NextDocument` — a **per-request** `timeout(120s)` (M0: 8.6 s at 300 dpi, but
  600 dpi and PDF on weak Wi-Fi — headroom; 65 s from the first edition of the plan —
  too little).

Hard rules (all — from M0, see `docs/escl-l2710dw.md`):

- `ScanSettings` — **a single line**; we generate it manually with
  `ScanParams::to_xml()` (`format!`), without a serde serializer: serde/quick-xml
  does not express mixed namespaces and will easily add a declaration/indentation.
  `quick-xml` — **parsing only** (caps/status, `NsReader`, matching by local
  name; the 0.4x API to be confirmed on docs.rs during implementation).
- `pwg:InputSource` (not `scan:InputSource`), `ScanRegions` is mandatory,
  coordinates in 1/300″, Platen A4 = `2550×3507` (from caps, not hardcoded).
- Resolutions — only from caps (`100/200/300/600`); `150` → a validation error
  (the device would silently substitute 300).
- `ColorMode`: `BlackAndWhite1`/`Grayscale8`/`RGB24`; `BlackAndWhite1` + JPEG →
  a validation error before `POST` (the device will answer `409`).
- Job state — only from `GET /eSCL/ScannerStatus` → `JobInfo/JobState`.
- After success/cancel — `DELETE` (treat 404 as success).

Validation in one place: `ScanParams::validate(&ScanCaps) -> Result<(), EsclError>`
(source, dpi, color, format, the «b/w + JPEG» pair).

Errors: `EsclError::{Timeout, Transport, Http{status, body_snippet}, Parse, InvalidParams(msg)}`
+ mapping to UI texts at the level of the commands («device busy» for 503,
«no paper in the tray» for 500+Feeder, etc.).

Unit tests (offline, `include_str!("../../fixtures/escl/...")` — the path does not
depend on cwd):

1. `capabilities.xml` → 4 resolutions `[100,200,300,600]`, 3 ColorModes,
   Platen+Adf, PDF+JPEG, regions `2550×3507` / `2550×4200`.
2. `ScanParams{Platen,300,Grayscale8,pdf}.to_xml()` is **byte-for-byte** equal to
   `fixtures/escl/scansettings-platen-300-gray-pdf.xml` (there is no trailing
   `\n` in the fixture) + a separate check `!xml.contains('\n')`.
3. `status.xml` → `Idle`/`ScannerAdfEmpty`; `status-job-active.xml` → 15 JobInfo,
   Pending/Processing/Completed/Canceled + reasons.
   **Careful:** in the fixture all `pwg:JobUri` are the same (redaction) — test the
   search for «its own» job on a separate inline-XML line, not on the fixture.
4. `validate()`: 150 dpi → error; `BlackAndWhite1`+jpeg → error; Feeder without
   support → error.
5. Mapping 409/500/503/timeout → `EsclError` variants.

## 5. IPC and the «Scan» screen

Commands (a thin layer, without logic):

- `get_capabilities() -> ScanCaps` — a cache in `Mutex<Option<ScanCaps>>` state,
  re-fetch on error;
- `start_scan(params: ScanParams) -> jobId` — **first synchronously** a preflight +
  `POST` (errors 409/500/503 are returned to the UI right away), then `tauri::async_runtime::spawn`
  to read out the document; `jobId` = path `/eSCL/ScanJobs/<uuid>`;
- `cancel_scan(jobId)` — validate that `jobId` starts with
  `/eSCL/ScanJobs/` and belongs to the configured device (the IPC boundary,
  PRD §5.5); then `DELETE` on a separate connection: `200` → canceled,
  `404` → the job has already finished on its own (not an error). Do not abort the
  fetch task: `410` in it is a normal completion (§1). Delete the temporary file
  unconditionally;
- `open_scan_folder()` — via `tauri_plugin_opener` **from Rust**
  (`app.opener().open_path(...)`), then JS permissions are not needed.

Events (`emit` → `listen`):

- `scan-progress { jobId, phase, pages }`, `phase` — the client-side stages:
  `created | scanning | done` (§1: status polling is not needed, `Completed`
  lags and cannot be a trigger);
- `scan-done { jobId, file }` (in PRD §9 it is currently `files[]` — bring the PRD to
  the actual M1 contract);
- `scan-error { jobId, message }`.

Saving: `scan_dir` from the config, the name `scan-YYYYMMDD-HHMMSS.pdf`, on a collision
within the same second — the suffix `-2`.

UI (vanilla TS, without a framework; the PRD §13.7 threshold — 500 lines of DOM):

- `ui/src/types.ts` — the IPC types (`camelCase`, like the serde structs);
- `ui/src/api.ts` — wrappers around `invoke` (`@tauri-apps/api/core`) and `listen`
  (`@tauri-apps/api/event`) — **not** `@tauri-apps/api/tauri` (that is v1);
- `ui/src/main.ts` — selects for source/dpi/color/format from `get_capabilities()`,
  a button with a disabled state and phases, errors as text, the path to the last file,
  «Open folder».

## 6. Tray and single-instance

- `tauri = { features = ["tray-icon"] }` (see §2).
- Icon: `.icon(app.default_window_icon().cloned().unwrap())` — otherwise on Linux
  the tray may be empty.
- Menu: «Show window», «Exit»; `show_menu_on_left_click(true)`.
  **On Linux tray events are not emitted at all** (menu only) — clicking the icon
  does not open the window, this is normal and is recorded in the README.
- `single-instance`: registered as the **first** plugin in the builder; in the callback —
  `show()` + `unminimize()` + `set_focus()`.
- Closing the window: `WindowEvent::CloseRequested` → `api.prevent_close()` + `hide()`;
  «Exit» → `app.exit(0)`. The behavior — in the README.
